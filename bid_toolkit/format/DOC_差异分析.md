> 目标：从招标文件提取排版格式要求 → 输出规则表 → 供标书脚本执行
> 解决：agent_epsilon排版时「自己逻辑自洽但对不上招标文件编号/格式」的问题

## 二、agent_epsilon排版出现的具体坑

根据观测到的问题（编号对不上、格式跑偏），推断出以下**5类坑**：

### 坑1：编号体系与招标文件不一致（最严重 ⭐⭐⭐⭐⭐）

**现象**：agent_epsilon自己生成了一套编号体系（如一、(一)、1.），但招标文件里的编号不是这样写的。

**根因**：没有从招标文件中提取真实的编号结构。

**现有工具的覆盖**：
- `fix_bid_format.py` 有 `scan_numbering_issues()` — **只检查自身连续性**，不是检查是否与招标文件一致
- `parse_bid.py` 有 `extract_outline()` — 提取了章节框架，但**没有输出为规则表**

**差距**：缺一个「招标文件编号 → 投标书编号一致性」检查。需要对比规则表中的编号格式vs实际投标书编号。

### 坑2：标题样式层级错误（⭐⭐⭐⭐）

**现象**：正文段落用了Heading样式，或标题层级跳级（Heading 1 → Heading 3）。

**根因**：docx模板的Heading样式没有与招标文件的章节结构对齐。

**现有工具的覆盖**：
- `fix_bid_format.py` 的 `scan_heading_hierarchy()` — 检测跳级和假标题
- `bid_engine.py` 的 `check_heading_styles()` — 也做了类似检测

**差距**：检测逻辑在，但没有「招标文件章节数 = 投标书标题数」的对账。

### 坑3：字体字号自行发挥（⭐⭐⭐）

**现象**：正文用了小四宋体，但招标文件要求五号仿宋。

**根因**：排版时用了bid-toolkit的默认配置（宋体小四1.5倍），没去招标文件里核实。

**现有工具的覆盖**：
- `parse_bid.py` 的 `extract_format_requirements()` 能提取字体字号
- `bid_engine.py` 的 config.yaml 支持自定义，但默认值是硬编码

**差距**：提取到了，但没**自动**应用到排版引擎。需要打通提取→配置的管道。

### 坑4：暗标信息残留（⭐⭐⭐）

**现象**：暗标却出现了页眉/页码/公司名称。

**根因**：没检测到招标文件是暗标，或没按暗标规则处理。

**现有工具的覆盖**：
- `fix_bid_format.py` 的 `scan_hidden_content()` — 检测隐藏文字/批注/元数据
- `bid_engine.py` 的 `apply_anonymous()` — 暗标模式实现
- `parse_bid.py` 的 `extract_disqualification_rules()` — 只抽废标规则，没抽暗标规则

**差距**：`parse_bid.py` 没提取暗标要求。`fix_bid_format.py` 只能检查不能自动脱敏。

### 坑5：页边距/行距/缩进不符合要求（⭐⭐）

**现象**：全文排版完才发现行距或页边距错了。

**根因**：排版前没定位到招标文件的格式要求段落。

**现有工具的覆盖**：
- `parse_bid.py` 的 `extract_format_requirements()` 能提取页边距/行距，但正则太少容易漏
- `format_rule_extractor.py` (NEW) 扩大了正则覆盖

## 五、agent_epsilon介入点

当agent_epsilon接到排版任务时，流程应该是：

```
招标文件PDF → format_rule_extractor → rules.yaml → agent_epsilon检查修改规则
       ↓                                                           |
  (校对：规则提取准不准) ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ←
       ↓ (确认准确后)
  bid_engine.py --config rules.yaml → 投标书.docx
       ↓
  排版后自动检查 vs rules.yaml
```

让agent_epsilon从「自己做排版全流程」变成「审核规则提取准不准 + 确认排版结果」。
