# content.json 结构规范

`render` 命令的输入文件。核心原则：**内容不写编号，编号由引擎自动生成**。

## 顶层结构

```json
{
  "meta": {
    "title": "项目名称",
    "bidder": "投标人名称",
    "date": "2026-08-31"
  },
  "body": [
    { "type": "h1", "text": "项目概述" },
    { "type": "p", "text": "段落文本..." }
  ]
}
```

`meta.title` 用于封面与页眉，`meta.bidder` 用于落款。

## 块类型

| 类型 | 必需字段 | 说明 |
|------|---------|------|
| `h1`~`h5` | `text` | 真实 Heading 样式，引擎自动编号（`第一章` / `1.1` 等由配置决定） |
| `hnum` | `text`（可选 `level`） | 序号标题，不进目录。`level` 0→`（1）`，1→`1）`，2→`①` |
| `p` | `text` | 正文段落，首行缩进由引擎统一处理 |
| `list` | `items` | 列表，支持三级嵌套 |
| `table` | `header`、`rows` | 表格，按章自动编号（表 1-1） |
| `figure` | `title`、`img` | 图片，按章自动编号（图 1-1） |

## 列表（支持嵌套三级）

字符串项与 `{t, children}` 对象可混用：

```json
{
  "type": "list",
  "items": [
    "一级项",
    { "t": "一级项（带子项）", "children": ["二级项 A", "二级项 B"] },
    { "t": "一级项", "children": [{ "t": "二级项", "children": ["三级项"] }] }
  ]
}
```

层级标记依次为 `（1）` / `1）` / `①`，由「列表」配置节控制。

## 表格

```json
{
  "type": "table",
  "title": "人员配置表",
  "header": ["序号", "岗位", "人数", "备注"],
  "rows": [
    ["1", "项目经理", "1", "持 PMP 证书"],
    ["2", "技术员", "3", "中级以上职称"]
  ]
}
```

`header` 不可为空，`rows` 每行长度建议与 `header` 对齐。

## 图片

```json
{
  "type": "figure",
  "title": "项目组织架构图",
  "img": "images/org_chart.png",
  "width_cm": 14.0
}
```

`img` 相对 content.json 所在目录。不传 `img` 则渲染为占位文本框，便于先定稿后补图。

## 硬规则

1. **绝不手打编号**——正文里不要出现「第一章」「一、」「表 1-1」，引擎自动渲染。
2. 标题只写文本，编号与对齐由引擎按配置处理。
3. 表格与图片的章节编号基于当前 `h1` 计数。
4. 段落不要手动加空格缩进。
5. 中文标点用全角：`（一）` 而非 `(一)`。

## 校验失败常见原因

| 报错 | 原因 |
|------|------|
| `未知 type='hnum'` | 类型不在白名单（合法：h1–h5 / p / list / table / figure / hnum） |
| `(list): 列表嵌套最多三级` | 层级超过三层 |
| `(list): 列表项必须是字符串，或 {t…}` | 混入了非法结构 |
| `(h1): 'text' 必须是非空字符串` | 标题文本为空 |

改完 JSON 直接重跑 `render` 即可，校验会给出精确位置（如 `body[11]`）。
