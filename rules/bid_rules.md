# 第一卷：核心原则（最高优先级）

## 铁律1：招标文件说什么我做什么，不多也不少

```
招标文件有要求 → 逐字对标，一字不差
招标文件没要求 → 弹性表述，不写死
招标文件没提的 → 不主动承诺额外义务/投入/资源
```

## 铁律2：除非招标文件明确要求，否则绝不给自己设限

**❌ 禁止写法（金额设限）：**
- 节日礼品/购物卡（200至500元）
- 慰问金500至2000元
- 旷工1日扣减3日工资
- 考核90分按100%发放、80分按90%...
- 任何具体金额的承诺

**❌ 禁止写法（主动承诺额外义务）：**
- "费用由XX公司承担"（培训费/考证费等，招标文件没说就不要主动提）
- "提供外部培训资源（如银行从业资格证培训、理财师培训等）"
- 招标文件未要求的额外投入/福利/资源

**✅ 正确写法：**
- 节日福利按公司福利制度执行
- 慰问帮扶根据实际情况确定
- 违纪处理按《劳动合同法》及公司规章制度执行
- 绩效考核与绩效发放挂钩（具体比例按银行考核标准执行）
- 培训方面按招标文件要求执行（没提就不额外承诺）

## 铁律3：绝对不在标书中主动暴露自己的短板或不足

**❌ 错误示范：**
- "虽然XX公司在银行零售外包缺乏直接业绩..."

**✅ 正确示范：**
- "XX公司在金融外包领域积累了丰富经验，涵盖银行、保险、交易中心等多类金融机构，在合规管理、人员体系化管理、银行岗位特性理解等方面具备深厚能力"

**心法：** 不提短板、直接说优势，把经验迁移过来包装成能力

## 铁律4：占位符零容忍（🔴 致命）

**❌ 禁止行为：**
- 遇到不确定信息时写"400-XXX-XXXX"、"13XXXXXXXXX"、"待填写"等占位符
- 写完后想着"后面再改"然后忘记

**✅ 正确做法：**
- 有不确定信息时**先问用户**，问清楚了再写
- 宁可先暂停写作去问，也不留占位符

**风险提示：** 占位符残留 = 直接废标！宁可多花时间确认，不省这一步。

**必搜占位符词汇（每次提交前全文搜索）：**
```
XX、AAA、____、【待填写】、采购人、胜任本项目主管
400-XXX-XXXX、13XXXXXXXXX 等联系方式占位
"待开通后告知"、"后续补充" 等模糊表述
```

# 第二卷：四段式审核流程（全局框架）

> **铁则：不可跳过任何阶段**

```
Phase 0: 弹药盘点 → Phase 1: 格式对照 → Phase 2: AI机审 → Phase 3: 人工逐字审核
```

**第零阶段不盘点，不开第一阶段。第一阶段不通过，绝不开第二阶段。**

## Phase 0：弹药盘点（动笔前）

1. 扫描项目组知识库可复用资产
2. 匹配项目章节 → 🟢真数据 / 🟡可适配 / 🔴需新写
3. 素材预整理归档
4. **【新增 v5.0】客户资料前置提取核对（详见第十卷）**
5. **【新增 v5.1】四件套必齐**（缺一不可，缺则禁开 Phase 1）：
   - ① **资质清单事实表** — 营业执照/许可证/授权委托书是否需要/法人是否到场等
   - ② **比选/招标关键数据表** — 采购数量、单价上限、合计上限、截止时间、地点、保证金、联合体限制
   - ③ **客户资料事实表**（第十卷四步流程产出）— 货品品牌/供应商/产地/型号/参数，逐项标注来源
   - ④ **绝对化用语黑名单** — 见铁律29，写之前先把禁用词刻进脑子

## Phase 1：格式对照

必须逐表、逐列、逐注释对照招标文件模板：
- 包件完整性（是否缺整个包件）
- 表格列数/列名对齐
- 注释文字未被篡改
- 签章区完整

## Phase 2：AI机审铁律

- [ ] 脱敏检查（100%命中率）
- [ ] 错别字与禁用词
- [ ] 数据交叉验证
- [ ] 法律风险扫描
- [ ] 编号连续性
- [ ] 日期一致性

## Phase 3：人工逐字审核

- [ ] 措辞恰当性
- [ ] 内容深度评价（关键章节篇幅是否达标）
- [ ] 跨文件一致性
- [ ] 上下文关联判断

# 第三卷：招标文件分析SOP（精准拆解）

**每次做标书前必须执行！**

## Step 1: 读取招标文件
- 完整阅读招标文件（招标公告、投标人须知、评标办法、合同条款、技术需求）

## Step 2: 提取评分表
- 提取所有评分项（分值/评分标准/具体要求）
- 标记分值高的重点项

## Step 3: 提取废标项
- 列出所有一票否决项（\*号条款、实质性要求）
- 标记必须响应的硬指标

## Step 4: 提取格式要求
- 判断通用/暗标/其他特殊格式
- 记录字体、字号、行距、边距等具体要求

## Step 5: 提取关键要求
- 人员数量/资质/服务期限/响应时间等硬指标
- 特殊资质要求（如劳务派遣经营许可证+人力资源服务许可证）

## 输出物（必须生成）

1. **评分项对照表**（评分项→对应章节→完成状态）
2. **废标项清单**（一票否决项→响应状态）
3. **格式配置单**（通用/暗标→具体参数）

# 第四卷：三层递进审核法（13步完整流程）

> **口诀：先保生死线（1-4），再保得高分（5-9），最后提印象（10-13）**
> **时间不够只查前4步，确保不废标！**

## 🔴 第一层：红线否决（先保生死线）

### Step 1: 废标项排查 ❌ 红线！
- 检查\*号条款、实质性要求是否全部响应
- 检查盖章签字完整性
- 检查投标保证金/保函是否符合要求

### Step 2: 信息核对 ❌ 红线！
- 项目编号一字不差
- 项目名称一字不差
- 落款日期按招标文件开标时间填写
- 投标人名称与营业执照一致

### Step 3: 企业资质 ❌ 红线
- 营业执照有效期
- 资质证书有效期（劳务派遣经营许可证、人力资源服务许可证等）
- 信用记录（中国执行信息公开网、信用中国）
- 过期一律更换！

### Step 4: 人员资质 ❌ 红线
- 人员证书真实有效
- 社保缴纳记录齐全
- 人员数量与配置表一致
- 信用记录无异常

## 🟠 第二层：核心内容（再保得高分）

### Step 5: 资格项检查 ⚠️ 严重
- 对照资格要求清单逐项打勾确认
- 不漏任何资格项
- 资格证明文件齐全

### Step 6: 评分项检查 ⚠️ 严重
- 对照评分标准确保每个得分点都有对应内容
- 评分项对照表逐一核对
- 高分值项重点优化

### Step 7: 技术符合性 ⚠️ 严重
- 方案针对本项目需求，不得照搬模板
- 地点一致性检查（黄浦海关/上港罗东教训）
- 服务范围与招标要求一致

### Step 8: 一致性审查 ⚠️ 严重
- 交叉验证：前文承诺 vs 后文配置
- 人员数量前后统一
- 金额数据前后一致
- 服务期限前后一致
- 技术指标前后一致

### Step 9: 分项报价验算 ⚠️ 重点！
- 单价×数量=总价，逐行验算
- 报价汇总 vs 分项合计一致
- 理解报价格式要求（先理解格式再填）

## 🟡 第三层：细节优化（最后提印象）

### Step 10: 格式对照 ✏️ 一般
- 标题层级、字体字号、排版规范
- 严格对照招标文件格式要求
- 暗标特殊要求（无封面/目录/页眉/页脚/页码）

### Step 11: 索引表检查 ✏️ 一般
- 目录页码对应关系准确
- 断点检查法：每检查完一项打勾确认
- 页码填写准确

### Step 12: 文字表述 ✏️ 一般
- 全文通读检查错别字、语病、标点符号
- 专业术语准确性
- **AI风格审查**（去AI味，见第五卷铁律9）

### Step 13: 可查询信息 ✏️ 一般
- 股东信息、法院执行信息等公开可查信息
- 能查的必须查
- 地点一致性复核（注册地、经营地与投标声明一致）

# 第五卷：内容审核铁律（致命错误=废标）

## 铁律5：去AI味（🔴 致命）

**禁用八股词汇（全文搜索逐条替换）：**

| 禁用词 | 替换建议 |
|--------|---------|
| 综上所述 | 直接删，或改为"因此" |
| 值得注意的是 | 直接删，或改为"需要关注" |
| 至关重要 | 改为"关键"或"重要" |
| 不可或缺 | 改为"必要" |
| 确保安全 | 改为"保障" |
| 赋能 | 改为"支持"或"助力" |
| 全流程 | 改为"全过程" |
| 全方位 | 改为"全面" |
| 深度融合 | 改为"紧密结合" |
| 显著提升 | 改为"明显提高" |
| 核心竞争力 | 改为"核心优势" |
| 战略高度 | 改为"从战略层面" |
| 此外 | 直接删 |
| 提供全方位 | 改写 |

**AI味特征：**
- 过度使用排比句
- 每段结尾总结"因此..."
- 形容词堆砌（"卓越的、先进的、完善的"）
- 空泛表述（"以客户为中心"但无具体措施）

**修复原则：** 用具体数据和事实替换空洞形容词

## 铁律6：脱敏检查（🔴 致命）

**每次项目配置不同，常见残留：**
- XX、AAA、\_\_\_\_、XXX、placeholder
- 上个项目名称（如"万家基金"→改为"厦门银行"）
- 上个项目岗位（如"运营岗/客服岗"→改为"零售财富业务服务经理"）

**检查方法：** 全文搜索禁用词，发现即替换

## 铁律7：法律条款检查（🔴 致命）

**逢引必查：** 引用任何法规前搜索"XX法是否存在"

| 错误表述 | 问题 | 正确做法 |
|---------|------|---------|
| "劳务外包暂行规定" | ❌ 该法规不存在 | 引用《劳动合同法》 |
| 《保守国家秘密法》适用于商业秘密 | ❌ 不适用 | 用《反不正当竞争法》 |
| "解释权归乙方所有" | ❌ 民法典认定无效 | 删除该条款 |
| "零中断零差错零事故" | ❌ 绝对承诺无效 | 改为"平稳过渡尽量避免" |
| 绩效双系数变相扣薪 | ❌ 违法 | 设保障下限：个人≥0.7，团队≥0.8 |
| 赔偿上限封顶 | ❌ 无效 | 改为协商方案 |

## 铁律8：模板套用检查（🔴 致命）

**跨行业模板残留必搜词：**
- 建筑施工、施工现场、安全帽、安全绳
- 职业病危害、树叶、取暖、做饭、洗衣粉
- 路灯、太阳能照明、消声器、蓝天救援队
- 卫健委、销售岗、行政岗、技术岗

**出现即删或替换！**

## 铁律9：角色定位检查（🔴 致命）

**自审口诀：** XX公司派人去干活，用甲方设备甲方场地甲方系统，只能管自己人

**❌ 禁止承诺：**
- 改造甲方设备
- 升级甲方系统
- 替甲方采购
- 承诺甲方业务指标（如营销业绩）

## 铁律10：逻辑一致性检查（🔴 致命）

**四维交叉验证：**
1. 同章内多个版本说法是否一致
2. 跨章时间线是否矛盾（培训时间vs到位时间）
3. 考核标准与实施方案是否对应
4. 人数口径是否统一（服务人数vs管理人数vs投标报价人数）

## 铁律11：数据来源验证

**所有量化指标必须附出处：**
- 流失率 → 来源哪里？
- 薪酬水平 → 来源哪里？
- 社保比例 → 来源哪里？（⚠️ 社保每年7月1日更新）
- 人员数量 → 与公司实际数据是否一致？

**无出处 = 减分，必须标注来源或删除**

# 第六卷：排版格式铁律（格式=第一印象）

## 铁律12：排版格式必须严格按招标文件要求

### XX公司系排版标准（明标）

**页面设置：**
- A4纸张
- 上下边距: 2.54cm
- 左右边距: **2.00cm**（不是3.17cm！Word默认值不对）

**字体字号（全部宋体，不用黑体）：**
- Heading 1: 宋体三号(16pt), bold, 左对齐
- Heading 2: 宋体小三(15pt), bold, 左对齐
- Heading 3: 宋体四号(14pt), bold, 左对齐
- Heading 4: 宋体四号(14pt), bold, 左对齐
- 正文: 宋体四号(12pt), 两端对齐
- 表格: 宋体五号(10.5pt)

**段落格式：**
- 正文: 首行缩进2字符, 行距1.5倍
- 表格: 单倍行距, 无缩进
- 图片: 无缩进, 居中
- Heading段前段后: Level1(12pt/6pt), Level2(8pt/4pt), Level3(6pt/3pt), Level4(4pt/2pt)

**表格样式：**
- 表头: 宋体五号(10.5pt), 加粗, 居中, 底纹填充
- 表体: 宋体五号(10.5pt), 垂直居中, 不自动换行
- 边框: Table Grid样式, 四边全黑实线(1pt)

### 暗标标准
- 字体：宋体四号常规字，不得加粗/加色/倾斜/下划线
- 行距：固定值30磅
- 无封面/目录/页眉/页脚/页码
- 上边距2.5cm，其余2cm
- 表格不得用图片格式插入
- 表内文字宋体四号常规字，无首行缩进

## 铁律13：表格样式必须与正文样式彻底隔离

**❌ 致命错误：**
- 表格段落使用"正文"样式 → 正文改缩进时表格跟着动

**✅ 正确做法：**
- 表格段落必须使用独立样式（如"Table Text"）
- 该样式设置：宋体五号、无首行缩进、无加粗无颜色
- 所有表格段落 `para.style = doc.styles['Table Text']`

## 铁律14：标题必须用Word可识别的Heading样式

- 一级：Heading 1（一、二、三...）
- 二级：Heading 2（（一）（二）...）
- 三级：Heading 3（1、2、3...）
- 四级：Heading 4（1.1）

**❌ 假标题：** 只是加粗加大的普通段落 → 目录识别不了
**✅ 真标题：** 应用Heading样式 → 目录可自动生成

## 铁律15：段落无多余空行

- 段前段后间距：0
- 段间距由行距控制，不用回车换行制造空行

## 铁律16：全角半角一致性

- 中文正文必须全角标点（。，、""《》）
- 禁止中文中混入英文引号/逗号/句号
- 阿拉伯数字后的序号（1. 2. 3.）可用半角
- 小数点可用半角

## 铁律17：Markdown加粗标记残留必查

**转Word前必须：**
```bash
grep -rn "\*\*" 投标文件
```
**零残留才能放行！**

## 铁律18：图片完整性及格式

**docx文本审核后必须肉眼开原件核对：**
- 图片/表格是否完整
- Word heading样式是否正确
- 拟派人员名单是否完整
- 管理层资质是否清晰

**图片插入规则：**
1. 图片段落必须清除首行缩进（图片不需要缩进）
2. 图片段落整体居中显示
3. 图片前后不要有多余空行
4. 图片段落独立样式，无缩进

## 铁律19：自动编号规则

- 标题必须用Word多级列表自动编号，禁止手动输入序号
- XX公司多级编号格式：一、→（一）→ 1、→ 1.1、
- 有模板时基于主模板制作，直接复制模板→清空内容→填入新内容

## 铁律22：三大标书类型差异对照表

### 22.1 类型判断优先级

拿到招标文件第一步：**判断标书类型**。

| 类型 | 关键词信号 | 内容大纲模板 | 格式模板 |
|------|-----------|-------------|---------|
| 服务标 | 服务方案、人员配置、服务期、考核 | service_outline.md | government.yaml |
| 货物标 | 交货期、安装调试、质保期、制造商、设备清单 | goods_outline.md | goods.yaml |
| 工程标 | 施工组织设计、工程量清单、建造师、安全生产 | engineering_outline.md | engineering.yaml |

> 工具支持：`bid_type_detection.yaml` 可自动识别类型。
> 判断不准时按"就高不就低"原则：工程标>货物标>服务标。

### 22.2 核心差异对照

| 检查项 | 服务标 | 货物标 | 工程标 |
|--------|--------|--------|--------|
| **中小企业声明函** | 视分包许可：不允许分包时只填自己，允许分包时须填全所有分包方 | 须填列所有主材/设备制造商 | 按工程类别填报 |
| **报价表结构** | 人员费用为主（岗位×月薪×月数） | 货物清单（名称×型号×数量×单价） | 工程量清单（项目编码×工程量×综合单价） |
| **资质要求** | 视具体服务类型：人力资源需许可证，物业需资质，保安需许可证等 | 生产许可证/代理授权书/3C认证 | 建造师证+安全生产许可证+建筑业企业资质 |
| **模板残留检查** | 检查货物/工程残留 | 检查服务/施工残留 | 检查服务/货物残留 |
| **质保条款** | 服务期承诺 | 质保期+响应时间+备品备件 | 回访保修期+保修范围 |
| **核心章节** | 服务方案+人员配置+管理制度 | 交货安装+技术参数响应+售后方案 | 施工组织设计+施工方案+安全文明施工 |
| **偏离表重点** | 服务标准偏离 | 技术参数偏离 | 工程技术规格偏离 |
| **验收标准** | 服务考核+满意度 | 到货验收+安装调试验收 | 竣工验收+分部分项验收 |

### 22.3 专项检查清单

**货物标必查：**
- ☐ 中小企业声明函是否填列所有制造商
- ☐ 质保期是否满足招标要求
- ☐ 交货期是否满足招标要求
- ☐ 技术参数是否逐条响应
- ☐ 报价表产地品牌与响应表是否一致
- ☐ 安装调试方案是否完整

**工程标必查：**
- ☐ 安全生产许可证是否有效
- ☐ 项目经理建造师证书是否匹配
- ☐ 工程量清单是否覆盖全部分部分项
- ☐ 施工组织设计是否含四大块（方案+进度+质量+安全）
- ☐ 安全文明施工措施是否完整

**服务标必查：**
- ☐ 资质证书是否齐全（按服务类型匹配：人力资源需许可证，物业需资质，保安需许可证等）
- ☐ 人员配置是否覆盖全部要求岗位
- ☐ 服务响应时间是否对标
- ☐ 中小企业声明函是否合规：不允许分包时只填自己，允许分包时须填全所有分包方

**新项目先判类型再填报！**

# 第十卷：素材前置提取流程（2026-06-27 负责人令）⚠️ 新增

**适用范围：** 所有涉及货品、设备、物资的标书（主业/副业/外包业务均适用）

**执行时机：** 收到客户资料后**立即执行**，不等临写

**核心原则：** 数据不全不准，禁止动笔写方案。AI不确定的数据必须标注"需人工确认"，不允许自己编。

## 四步流程

### 第一步：提取

**操作人：** 接活Agent（执行Agent/自动化工具等）

从客户提供的所有资料中提取关键数据：

| 资料类型 | 提取内容 |
|---------|---------|
| 检测报告 | 产地、品牌、型号、技术参数、认证编号、供应商名称 |
| 产品说明 | 规格参数、材质、颜色、尺寸、包装信息 |
| 资质证书 | 证书编号、有效期、发证机构 |
| 价格清单 | 单价、数量、总价、折扣 |
| 合同/订单 | 交货期、付款方式、质保期 |
| 图片 | 确认图片与实际描述产品是否一致 |

**工具：** 用 `bid_parse.py` 或 `odl-pdf` 解析文档提取结构化数据

### 第二步：核对

**操作人：** 接活Agent初核 + 负责人/维护者复核

1. **纵向核对** — 同一份资料内部数据是否自洽（如检测报告上的产地、型号、参数是否一致）
2. **横向核对** — 不同资料间同一数据是否一致（检测报告的产地 vs 产品说明的产地）
3. **交叉比对** — **检测报告/产品资料中的产地、供应商等信息 vs 工具生成的产品简介**，确保对得上
4. **矛盾标记** — 发现矛盾数据的，标注来源出处，标记为🔴待确认

### 第三步：标注疑问

**操作人：** 接活Agent

AI或接活人对以下情况必须标注**「⚠️ 需人工确认」**，禁止自行编造：
- 不确定的产地/供应商名称
- 不全的产品型号/参数
- 模糊的认证编号
- 客户资料中没有的数据

**标注后通知负责人/维护者人工核对。**

### 第四步：形成数据事实表

**操作人：** 接活Agent → 输出给写方案Agent

所有确认无误的数据整理成数据事实表，包含：

| 字段 | 值 | 来源文件 | 确认状态 |
|------|----|---------|---------|
| 产品名称 | XX产品礼盒 | 报价单_P3 | ✅ 已确认 |
| 品牌 | 中粮 | 产品说明_P1 | ✅ 已确认 |
| 产地 | 山东青岛 | 检测报告_P2 | ⚠️ 需人工确认 |
| 规格 | 500g/盒 | 报价单_P3 | ✅ 已确认 |

**数据事实表作为派活给写方案Agent的唯一数据源。**

## 典型错误案例（今日实战教训）

**错误流程：**
客户资料 → 直接扔给执行Agent写 → 执行Agent编造产品产地/供应商 → 负责人返工修改 → 耗时翻倍

**正确流程：**
客户资料 → 提取核对 → 数据事实表 → 扔给执行Agent写 → 基于核实数据，无需返工

### 🔥 v5.1 增补：2026-06-27 执行Agent v6 事故链复盘

**事故链（5 连环）：**
1. **资质提取不全** — 漏判"法人本人到场可豁免授权委托书+被授权人身份证"

# 第十三卷：标书分工与协作机制

## 串标隔离规则

- **陪跑标** → 一人从头干到底，不拆分，避免交叉污染
- **主标（XX公司/XX服务等）** -> 分工协作，大标书拆任务跑得快
- **多标并行+不同投标单位** → 🔴 严格隔离，一人一公司，绝不串人
- 核心：不同公司的标书之间不能有任何信息交叉（模板/措辞/格式习惯）

## Agent分工定位

| Agent | 定位 | 适合 | 不适合 |
|-------|------|------|--------|
| 执行Agent | 快速执行型 | 陪跑标、快速执行、新工具试跑 | 深度创造性工作 |
| 审核Agent | 稳重型 | 标书审核、法务把关、大文件处理 | — |
| 排版工具 | 本地管家 | 文件筛选、格式转换、排版、图像处理 | 创造性写作 |
| 自动化工具 | 架构师 | 系统搭建、深度开发、夜间运维 | — |
| 维护者 | 统筹调度 | 任务分配、终审、兜底 | — |

## 派活铁律

- 每次派活，任务书第一句必须写：「基于主模板制作，复制模板→清空内容→填入新内容」
- 不写这句 = 派活不合格
- **设备/物资类标书：必须先经过第十卷素材前置提取流程，再派活写方案**
- 需要补充的内容标黄色高亮，防漏
- 每条任务末尾必须标注汇报方式
- **有疑问就问**：不确定的事不闷头干

## 文件互传规则

- 执行Agent/审核Agent在负责人本地电脑，文件传到服务器中转
- 服务器路径：<临时工作目录>
- 审核路径优先走脚本工具链

# 第十四卷：AI派活指令规范（2026-06-27 负责人令）⚠️ 新增

## 根源问题

# 第十五卷：代写业务专项铁律（v5.1 新增 · 2026-06-27 某货物标 v6 实战）

> **适用范围：** 主业（XX公司名义）+ 副业（帮客户名义投标）通吃。
>
> **底层逻辑：** 「客户给的就是甲方意志，AI 不替客户做主。」

## 铁律27：代写业务边界铁律

**核心原则：** 代写=辅助，不是接管。客户没让动的地方，碰都别碰。

**✅ 可以主动碰：**
- 错别字（如"技木→技术"）
- 绝对化用语（见铁律29）
- 货品/供应商前后不一致（见铁律28）
- 结构残缺的章节（如客户没写完应急方案、验收标准）
- 格式排版（字体/缩进/行距）

**❌ 绝对不碰（除非客户明确点头）：**
- **报价区**（单价/合计/总金额/大写金额）
- 客户没要求加的硬性数据（税额/保证金/折扣）
- 客户原文里的数字（数量/规格/型号），即便看着不对也先标黄问

**典型场景：**
- 客户单价表没写合计 → **不要替他加**，他没写自有他的考虑（可能跟招标方对过，可能模板就这样）
- 想加 → 截稿前问客户点头才能加
- 替客户签字 = 比废标还伤口碑

**心法：** 「碰报价 = 越界；碰错别字 = 加分。分清楚边界。」

## 铁律28：货品多处一致性核对铁律

**根因：** 同一货品名常在标书 4 个位置出现，AI 改一处忘改另一处 → 前后供应商/品牌/产地打架 → 评委一眼看穿 → 扣印象分甚至质疑串标。

**货品名常出现位置（必须逐处对账）：**
| 位置 | 字段 | 检查点 |
|------|------|--------|
| 报价表 | 品牌/规格 | 与产品介绍/检测报告对得上 |
| 产品介绍章节 | 品牌/产地/供应商 | 与报价表/检测报告对得上 |
| 检测报告引用 | 委托方/受检方 | 与产品介绍对得上 |
| 供应商资质表 | 供应商名称 | 与产品介绍/检测报告对得上 |

**操作要点：**
- 每个货品建一行「四方对账卡」：货品名 / 报价表写啥 / 产品介绍写啥 / 检测报告写啥 / 供应商表写啥
- 四列必须一字不差（含品牌后缀，如"裕庆堂羊肚菌"不能少"裕庆堂"）
- **工具落地：** 后续加 `check_product_consistency.py` 批量比对

**今日实战教训（案例项目A案）：** 案例项目A在某表格上写的供应商前后不一致，负责人本地手改。

## 铁律29：绝对化用语扫描铁律（🔴 致命级）

**法律依据：** 《广告法》第九条——绝对化用语涉嫌违法广告，招投标场景可能被判定**无效投标**或被甲方提前剔除。

**必删词黑名单（v5.1 首发，持续扩充）：**

| 类别 | 禁用词 |
|------|--------|
| 排名类 | 世界第一/全国第一/行业第一/省内第一/最大/最优/最佳/最权威/最先进 |
| 唯一类 | 独家/唯一/唯一指定/独有 |
| 王者类 | 中华XX王/中华XX之冠/XX之王/王牌 |
| 极限类 | 全国最丰富/全球最大/最高品质/最低价格 |
| 顶级类 | 顶级/顶尖/顶峰/极致/卓越（慎用） |

**✅ 安全替代词：**
- 业内领先 / 品质优良 / 具代表性 / 广受认可 / 行业知名 / 优质 / 较为先进 / 较高品质

**操作要点：**
- 写完后必须用脚本扫一遍：`bid_engine.py --check-absolute <docx>`（待加开关）
- 当前临时方案：`grep -E "世界第一|全国第一|最大|最优|最佳|最权威|独家|唯一|XX王" <文本>`
- 检测报告引用客户原话时，**保留原文不改**（如"中华枣王"是产品名注册商标时可保留，单独写文案描述就要改）

**今日实战（v6 案）：**
- ❌ 中华枣王 → ✅ 新疆红枣的代表性品种
- ❌ 多糖含量全国丰富 → ✅ 多糖含量丰富

## 铁律30：检测报告字段优先级铁律

**核心规则：** 写产品产地/委托方/品牌/供应商时，按检测报告字段优先级取值：

```
委托方 > 受检方 > 生产方
```

**原理：**
- 检测报告"委托方" = 谁出钱送检 = 通常就是品牌方/经销商，与商业关系直接挂钩
- "受检方" = 被检测的样品来源 = 可能是工厂代检
- "生产方" = 实际生产地 = 可能是 OEM 代工厂，写出来反而暴露非自有产能

**反例（错误处理）：**
- ❌ AI 自作主张换成"更高端"的名字（如把检测报告的"裕庆堂"换成"云南某菌业"）
- ❌ 写检测报告"生产方"而把委托方丢掉（暴露代工底牌）

**今日实战（案例项目B）：** 负责人按检测报告委托方写客户名 = 正确操作。

## 铁律31：设备/车辆"实有"vs"方案"分离铁律

**根因：** AI 看到"应急保障/服务方案"章节就想吹设备数量，导致资质页 1 辆车被吹成 3 辆 → 现场履约对不上 → 验收翻车 + 信用扣分。

**严格分离规则：**

| 章节类型 | 数据来源 | 写法 |
|----------|----------|------|
| **资质页 / 拟投入设备表** | 公司实有资产清单 | 只写实数（如"沪A·XXXXX 轻型厢式货车 1 辆"），**禁止编数** |
| **实施方案 / 应急保障章节** | 业务弹性表达 | 写"基础运力 1 辆自有 + 不足时外协调度第三方运力" |
| **服务承诺章节** | 能力承诺 | 写"24 小时内调度补充运力" |

**❌ 禁止写法：**
- 资质页"拟投入车辆 3 辆"（实有 1 辆）
- 应急方案"调用公司车队 5 辆"（公司只有 1 辆）

**✅ 正确写法：**
- 资质页：「沪A·XXXXX 轻型厢式货车 1 辆（本公司所有）」
- 应急方案：「基础运力以本公司自有车辆为主，旺季或紧急情况通过合作运力调度。」

**心法：** **资质页 = 验收依据，吹不得；方案页 = 业务能力，可弹性。**

**今日实战（v6 案）：** 资质页实有 1 辆沪A·XXXXX，应急方案被 AI 编成 3 辆 → 负责人发现后手改。

## 铁律32：资质硬性件本人到场豁免规则

**核心规则：** 法定代表人**本人到场**递交投标文件时，可豁免：
- 法定代表人授权委托书
- 被授权人身份证复印件

**必须保留：**
- 法定代表人身份证复印件
- 营业执照副本
- 行业许可证（如食品经营许可证）
- 财务/业绩等其他评分项资料

**判断流程：**
1. 招标/比选文件是否明确要求"必须授权他人投标"？→ 是 → 必须开委托书
2. 没要求？→ 法人能否本人到场递交？→ 能 → 豁免委托书
3. 法人到场 → 必须带身份证原件，便于现场核验

**典型场景（v6 案）：** 解陆军（法定代表人）本人到场递交 → 豁免授权委托书 = 正确处理。

**操作要点：**
- 这条要写进招标文件分析 SOP 的「资质硬性件清单」环节
- 派活给 Agent 时，资质清单事实表里要明确写："法人是否到场 = 是/否"，再决定授权委托书章节是否启用
